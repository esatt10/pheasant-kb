Write the complete Terraform configuration for the platform below, as providers.tf, variables.tf, main.tf, outputs.tf and terraform.tfvars.example.

Provider rule: use azurerm for every resource it supports, and azapi only for a resource azurerm does not provide.

Requirements. Implement every numbered item as resource blocks:
1. Governance: a new subscription alias, placed under a management group.
2. A resource group for the platform.
3. Network: a virtual network with subnets for workloads and for private endpoints.
4. Private access: private endpoints for the Foundry account, the Key Vault and the storage account, with private DNS zones so that clients inside the virtual network reach each service by its usual name.
5. A Key Vault.
6. A storage account.
7. Identity: a user-assigned identity with role assignments on the resources it uses.
8. AI: an AI Foundry (AIServices) account with a Foundry project, and cognitive deployments for gpt-6-luna and text-embedding-3-small.
9. Observability: a Log Analytics workspace, workspace-based Application Insights, and diagnostic settings that send platform logs to the workspace.
10. AI gateway in front of the model deployments:
    a. an API Management instance (StandardV2);
    b. an API that exposes the Foundry endpoint;
    c. failover: two backends with circuit breaker rules, combined into a load-balanced backend pool, so that when one backend is unavailable the other serves the same requests;
    d. an API policy applying llm-token-limit and llm-emit-token-metric;
    e. an Application Insights logger with an API diagnostic;
    f. a Foundry connection of category ApiManagement that points to the gateway.

Design rules:
- Each component should do the job stated for it above in a working deployment, with the supporting resources its documentation pairs it with.
- Declare each sub-component as its own top-level resource rather than as an inline block, so other components can reference it directly.
- Where a resource has a field that selects what kind of thing it is (a type, kind or mode), set it explicitly to the value for the kind asked for.
- Connect components by reference (ids, names), never by repeated literals, and write each reference to another resource's attribute in the form the provider documentation's examples use, including list indexes.
- Abstract every environment-specific value into a variable with a dummy placeholder default; resource blocks refer to variables and never contain a placeholder literal.
- Where the documentation leaves a value open, use a placeholder variable rather than leaving the component out.
