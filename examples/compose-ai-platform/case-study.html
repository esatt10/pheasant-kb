1 · The idea

Let the region do the reading

Building this platform from documentation means reading about two dozen reference pages, plus the Microsoft Learn guidance that ties them together. An agent can do that itself, but every page it reads costs context on its own, more expensive model, and nothing checks what it writes against the pages it skimmed. compose_artifact divides the work by what each side does well.

2 · The corpus

Six collections, registered and corrected over MCP

Each collection was registered with register_source and pinned to released versions: azurerm pages at the v5.12.0 tag, AzAPI resource specs at API versions AzAPI v2.13.0 accepts. One page was added during this test. The gateway needed to authenticate to Foundry with a managed identity, and the corpus had no reference for that policy; pheasant said so in not_covered rather than inventing it. One edit_source_urls call added the Learn page.

4 · What validate cannot see

The agent’s review, and where each fix came from

Every round passed terraform validate. Validate proves the types, arguments and references exist in the released providers; it cannot tell that a backend pool is not declared as a pool, or that a role is granted to an identity that does not exist. The agent read each result for that, and the region made each correction from the documentation, editing the earlier artifact rather than writing a new one.

#What the agent foundFixed inWhat the region wrote, and from which page

The round-2 request asked for the principal ID “in the form the provider documentation’s examples use”. The examples use identity[0].principal_id for a system-assigned identity, and the region applied the form to a user-assigned one. A request that leans on a convention can carry it to a case it does not fit; finding 6 is that case, caught in the agent’s second review.

7 · Limits and how to reproduce

    
What this does not show

    

      
One sessionThe three calls are one run, not a reliability figure. Across the night, single compositions of this request validated in most runs, and the misses were what §5 fixed. Re-run before relying on it.

      
The design review was the agent’spheasant checks identifiers, references, required arguments, invented types and stated purposes. The six findings in §4 came from the agent reading the result. A request that states those purposes up front needs fewer of them.

      
Validate is not plan or applyRole names, DNS zone names, model versions and diagnostic categories are placeholders, and not_covered says so. Whether Azure accepts the values is untested.

      
Jobs live in the API processA region restart loses them; previous_job then refuses and names the history route, which uses the artifact in the last turn as the draft.

      
LatencyA full composition takes about 5 minutes and a revision about 2. Ordinary questions are unaffected (measured: p50 3.10 s against 3.34 s before, paired median −0.01 s).

      
The region’s own accept gate is not the testIt scored round 1 grounded p = 0.00 on an artifact that validated; its thresholds were calibrated on short answers, so for artifacts it reports and never acts.
